# Rediff Email Integration

## Architecture

`Salesoorja evidence -> deterministic qualification -> outreach suppressions -> CSV handoff -> Rediff_Email_System -> Rediff SMTP -> Rediff logs/reports`

Salesoorja owns research, facility and person truth, qualification, contact verification, `READY_FOR_EMAIL`, suppression state, campaign metadata, and reply/enquiry state. The existing Rediff project owns SMTP credentials, MIME generation from its HTML template, connection handling, pacing, retry behavior, and transport reports.

The integration uses a **structured CSV handoff** through `backend/services/rediff_sender_adapter.py`. Salesoorja does not import the external project, read its configuration, open SMTP, or run it as a subprocess. This is the safest boundary because the current Rediff test mode still establishes SMTP and redirects mail to internal addresses.

## Existing Rediff System

- Project: `C:\Users\HP\OneDrive\Desktop\Rediff_Email_System`
- General entrypoint: `campaign_runner.py`, function `run_campaign(...)`
- Explicit production executor: `execute_production_campaign.py`
- Legacy sender: `send_email.py`
- Input: UTF-8 CSV; current source schema uses `LEAD_ID`, `COMPANY_NAME`, `FACILITY`, `LOCATION`, `SCORE`, `OPPORTUNITY_CLASS`, `DEMAND_EVENT`, `WHY_CALIBRATION_NOW`, contact fields, `READY_FOR_EMAIL`, `TRIGGER`, and `CALIBRATION_CATEGORY`. Its normalizer also accepts Salesoorja's newer uppercase aliases such as `COMPANY`, `CONTACT_NAME`, `EMAIL`, `TRIGGER_EVENT`, and `CALIBRATION_OPPORTUNITY`.
- Subject and HTML: generated by Rediff's `personalizer.py` and `html/email.html`; not supplied as authoritative rendered copy by Salesoorja.
- CC: transport-level `config.CC_ADDRESS`; row-level CC is not consumed by the current sender. Salesoorja includes environment-driven CC in handoff metadata for operator verification.
- Duplicate protection: production `SENT` history in `Outreach_Report.xlsx`, default 14 days.
- Pacing: configurable `SEND_DELAY_SECONDS` between production sends.
- Retry: the explicit production executor retries an SMTP exception once after two seconds; the general campaign runner has no send retry.
- 421: no dedicated 421 reconnect flow was found.
- Resume: no dedicated resumable batch checkpoint was found; history-based duplicate checks provide partial replay protection.
- Logs/reports: CSV logs plus `Outreach_Report.xlsx`.
- Attachments: no active attachment handling was found.
- Threading: no active `Message-ID`, `In-Reply-To`, or `References` handling was found. The Salesoorja handoff carries these fields for future compatibility, but the current Rediff sender must be extended before same-thread delivery is real.

## Safety Contract

Defaults are `REDIFF_SENDER_ENABLED=false`, `REDIFF_TEST_MODE=true`, and `OUTBOUND_TEST_MODE=true`. Test mode never writes a production queue file, imports Rediff modules, starts a subprocess, or opens SMTP. A qualifying synthetic record returns `DRY_RUN_READY` only.

Production handoff requires all of the following:

- `READY_FOR_EMAIL=YES`
- Existing Salesoorja qualification state permits production send
- Verified current employment and functional ownership
- Verified trigger and exact facility
- Mailbox-verified, person-specific email
- Real provenance, not mock/test/demo/synthetic
- No bounce, opt-out, meaningful reply, or 14-day duplicate
- Existing Rediff system path is available
- Both global and Rediff test modes are disabled

A score never authorizes handoff. Production success writes one CSV queue file and returns `QUEUED`; it never returns `SENT`. `SENT` is accepted only when a later Rediff receipt explicitly reports transport success. SMTP acceptance remains distinct from inbox delivery.

## Configuration

- `REDIFF_SENDER_ENABLED`
- `REDIFF_TEST_MODE`
- `REDIFF_SYSTEM_PATH`
- `REDIFF_HANDOFF_DIR`
- `REDIFF_CC_ADDRESSES`
- `REDIFF_DUPLICATE_WINDOW_DAYS`

No SMTP credentials are added to this integration. Existing Salesoorja direct SMTP code remains in place because campaign routes still reference it; removing it is outside this safe, incremental change.
